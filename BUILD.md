# Building & Developing LINEA

This document provides complete instructions for configuring your development environment, building the application from source, running automated test suites, and deploying/debugging LINEA on Android devices or emulators.

---

## 1. System Requirements & Toolchain

To build LINEA, ensure your workstation meets the following prerequisites:

| Component | Minimum Version | Recommended Version |
|---|---|---|
| **Operating System** | Linux (Ubuntu 22.04+ / Arch / Debian), macOS 13+, Windows 11 (WSL2) | Linux x86_64 |
| **Java Development Kit (JDK)** | OpenJDK 17 | OpenJDK 17 (Temurin or Android Studio bundled) |
| **Android SDK Platform** | API Level 37 (Android 17) | API Level 37 (`platforms;android-37`) |
| **Android SDK Build-Tools** | 35.0.0 or 37.0.0 | `build-tools;35.0.0` |
| **Android NDK** | Not required (100% Kotlin/Java runtime) | N/A |
| **Gradle** | 8.11+ (Managed via `./gradlew` wrapper) | Wrapper specified |

### Environment Variables
Verify that `ANDROID_HOME` or `ANDROID_SDK_ROOT` is configured in your shell profile:

```bash
export ANDROID_HOME=$HOME/Android/Sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/emulator
```

Create a `local.properties` file in the project root if not already generated by Android Studio:

```properties
sdk.dir=/path/to/your/Android/Sdk
```

## 3. Building from Command Line

Use the included Gradle wrapper (`./gradlew`) for all build targets.

### 3.1. Compile Source Code
To verify that all Kotlin source code, Room KSP processors, and Hilt code generators compile cleanly:

```bash
./gradlew compileDebugKotlin
```

### 3.2. Assemble Debug APK
Generates an unminified, debuggable APK signed with the default debug keystore:

```bash
./gradlew assembleDebug
```
The output binary will be located at:
```
app/build/outputs/apk/debug/app-debug.apk
```

### 3.3. Assemble Release APK
Generates an optimized release APK:

```bash
./gradlew assembleRelease
```
The output binary will be located at:
```
app/build/outputs/apk/release/app-release-unsigned.apk
```

> **Note**: To sign the release APK for distribution, provide your signing keystore configuration via environment variables or in `app/build.gradle.kts`:
> ```bash
> jarsigner -verbose -sigalg SHA256withRSA -digestalg SHA-256 \
>   -keystore my-release-key.jks \
>   app/build/outputs/apk/release/app-release-unsigned.apk alias_name
> ```

## 4. Running Tests & Quality Verification

### 4.1. Unit & Robolectric Tests
Executes local unit tests covering the deterministic rules engine, T9 prefix search, Room schema validation, and Telecom state machine:

```bash
./gradlew testDebugUnitTest
```

HTML test reports are generated at:
```
app/build/reports/tests/testDebugUnitTest/index.html
```

### 4.2. Android Lint
Scans the project for performance bottlenecks, accessibility issues, deprecated APIs, and resource leaks:

```bash
./gradlew lintDebug
```

## 5. Deployment & Device Installation

### 5.1. Install to Connected Device / Emulator
Ensure your device or emulator is connected via ADB (`adb devices`):

```bash
./gradlew installDebug
```

Launch the application directly via ADB:

```bash
adb shell am start -n com.ryanshelby.linea/.MainActivity
```

### 5.2. Grant Necessary Telephony Permissions
While LINEA requests permissions at runtime, you can grant them immediately via ADB for automated test sessions:

```bash
adb shell pm grant com.ryanshelby.linea android.permission.CALL_PHONE
adb shell pm grant com.ryanshelby.linea android.permission.READ_PHONE_STATE
adb shell pm grant com.ryanshelby.linea android.permission.READ_CONTACTS
adb shell pm grant com.ryanshelby.linea android.permission.WRITE_CONTACTS
adb shell pm grant com.ryanshelby.linea android.permission.RECORD_AUDIO
adb shell pm grant com.ryanshelby.linea android.permission.POST_NOTIFICATIONS
adb shell pm grant com.ryanshelby.linea android.permission.READ_CALL_LOG
adb shell pm grant com.ryanshelby.linea android.permission.WRITE_CALL_LOG
```

### 5.3. Set as Default Phone Dialer
To test full native call interception and cellular hardware management, designate LINEA as the system default dialer:

```bash
adb shell telecom set-default-dialer com.ryanshelby.linea
```

To verify the active default dialer:

```bash
adb shell telecom get-default-dialer
# Output should return: com.ryanshelby.linea
```

## 6. Telephony & Telecom Debugging Commands

When working with `InCallService`, `ConnectionService`, and audio routing, ADB provides powerful diagnostic inspection utilities:

### Inspect Active Telecom Calls
```bash
adb shell dumpsys telecom
```

### Check Registered PhoneAccount Handles (Dual SIM)
```bash
adb shell dumpsys telephony.registry
```

### Simulate an Incoming Call (Emulator Only)
```bash
adb emu gsm call +15552345678
```

### Simulate an Outgoing Call
```bash
adb shell am start -a android.intent.action.CALL -d tel:5550199
```

### Inspect Room SQLite Database
```bash
adb shell "run-as com.ryanshelby.linea sqlite3 databases/linea_database.db 'SELECT * FROM contacts;'"
```

## 7. Troubleshooting & FAQ

#### Q: Gradle fails with `Target SDK 37 is higher than the compile SDK supported by Android Gradle Plugin`
**A:** Ensure you are running Android Gradle Plugin 8.7+ and Gradle 8.11+. API level 37 corresponds to Android 17. Make sure your Android SDK manager has `platforms;android-37` installed.

#### Q: The in-call screen does not open when placing a call.
**A:** Make sure LINEA is set as the system default dialer. Non-default dialers on Android cannot bind to `InCallService` or display the system call management UI. Run `adb shell telecom set-default-dialer com.ryanshelby.linea`.

#### Q: Audio routing (Speaker/Earpiece) doesn't toggle.
**A:** On physical devices, audio routing is governed by `CallAudioState`. Verify that the device has `android.permission.MODIFY_PHONE_STATE` or is the designated default dialer invoking `setAudioRoute(...)` via `CallManager`.
